A. 日本のB2B/バーティカルSaaS・プロダクトマネジメント

LayerX「バクラク」、導入時の初期設定を自動化するAIエージェント機能をリリース

2026年8月20日 09:00発表

株式会社LayerXが、経費精算・申請などの「バクラク」シリーズにおいて、導入初期の 設定作業を自動化する「初期設定ガイド」「初期設定エージェント」の提供を開始した。 組織図やユーザー情報など、社内で普段使っている資料をアップロードするだけで、 AIエージェントがバクラクのインポート形式に自動変換し設定を完了する。手作業での 取り込み負担を減らし、導入期間の短縮を狙う。

B. AI/LLM・開発ツール

Claude Code、結果を簡潔に返す「Concise」出力スタイルを追加

2026年8月20日（v2.1.237）

AnthropicのClaude Codeが、前置きや実況的な説明を省き結果から先に示す組み込み 出力スタイル「Concise」を追加した。作業の丁寧さは維持したまま応答を簡潔にする 狙いで、`/config` の Output style から選択できる。同バージョンでは、LLMゲートウェイ や独自base URLを使うセッションでのプロンプトキャッシュ不具合も修正された。

出典: Claude Code Changelog（公式）

Vercel Functions、Bun 1.4に対応

2026年8月20日

Vercel Functionsが、ZigからRustへ全面書き換えされたBun 1.4に対応した。2,900件超の Issueを解消し、Node.js互換テストの通過数も1,500件以上増えている。破壊的変更を 含むため、`vercel.json` で `bunVersion` を `1.4.x` に設定する明示的なオプトイン方式で 提供される。

出典: Vercel Changelog（公式）

GitHub、コードスキャン警告の却下理由に「Mitigated（軽減済み）」を追加

2026年8月20日

GitHubのコードスキャン機能に、脆弱性がコード上は残るもののファイアウォールや ネットワークポリシーなど外部の制御でリスクが軽減されている場合に使う却下理由 「Mitigated」が追加された。「Won't fix」とは区別して記録でき、正式な例外承認 プロセスとの整合性を高める。

出典: GitHub Changelog（公式）

GitHub Code Quality、専用のActionsパスに分離

2026年8月20日

これまでコードスキャンと共有していたGitHub Code Qualityのワークフロー実行が、 専用パス「dynamic/github-code-quality/codeql」と独立したアクター 「github-code-quality」に切り替わった。ワークフロー実行履歴やActions使用量 レポート上で、コード品質の実行とコードスキャンの実行を区別できるようになる。

出典: GitHub Changelog（公式）
